# Security audit, Slow Horizons mint + Game Boy Labs site (2026-10-18)

Scope: gb-seed-lab @ 510c786 (server/src, server/scripts, web/, docs/SERVER-SETUP.md, LOGBOOK up to "server-side
security pass"), gameboy-labs-site @ 718d6f4. Report only: no project file changed except this one.

Method: code review; local server on devnet (`DEV=1`, port 18791, throwaway `DATA_DIR`/`KEY_FILE` in a scratch
dir, every config var exported explicitly so `server/.env` could not apply, fake serial port; stopped afterwards);
about 15 read-only GETs to www.gameboylabs.xyz / api.gameboylabs.xyz (headers and status codes only, no fuzzing);
`npm audit --omit=dev`; git history pattern search of both repos. Not read: `.keys/*`, `.env` values, Cloudflare
files (only `ls -l` and key names).

Severity is for the mint as deployed (mainnet, closed until launch). "(verify)" = not proven here.

## Critical

### C1. One request kills the server (remote, unauthenticated)

- **Where:** `server/src/index.mjs:493` `const url = new URL(req.url, 'http://x');` runs in the `http.createServer`
  callback, outside `route(...).catch()`. A throw there becomes an `uncaughtException`, and line 49 then calls
  `process.exit(1)`.
- **Exploit:** a request target that WHATWG URL rejects, e.g. `GET //x:99999`, `GET //%`, `GET //[`.
  `curl --path-as-is 'https://api.gameboylabs.xyz//x:99999'` once every 10 s (launchd `ThrottleInterval` 10) keeps
  the mint down for good. A piece being drawn is aborted and redrawn on each restart, and every restart sends a
  `crash` alert.
- **Evidence (local, devnet):** `curl --path-as-is 'http://localhost:18791//x:99999'` -> connection dropped, then
  `/api/health` -> refused, process gone; the log shows the stack from `parserOnIncoming`. In Node 25.9:
  `new URL('//x:99999','http://x')`, `'//%'`, `'//['` and `'http://['` all throw `ERR_INVALID_URL`.
  Reachability through Cloudflare + cloudflared was **not tested live** (it would take down production). `//x:99999`
  is plain ASCII, and Go's `URL.RequestURI()` keeps a leading `//` path as is, so it very likely passes (verify on
  a staging tunnel).
- **Fix:** parse inside a try and answer 400:
  ```js
  const server = http.createServer((req, res) => {
    let url;
    try { url = new URL(req.url, 'http://x'); } catch { res.writeHead(400); return res.end(); }
    route(req, res, url).catch(...);
  });
  ```
  Also do the same in `scripts/demo.mjs`. Keep exit-on-uncaught (state may be bad), but no request input should be
  able to reach it. Add a regression test that sends `//x:99999`.

## High

### H1. One payment can become two pieces (race in `handlePayment`)

- **Where:** `index.mjs:70-101` (`handlePayment`). The guard `if (state.usedSignatures[signature] || ...)` runs
  before `await sol.inspectPayment(...)`. The signature is only recorded after that await (line 94, or line 84 for
  refunds). Two callers run for the same signature: the watcher `poll()` (every 8 s) and the per-submit loop at
  line 445 (every 5 s for 60 s).
- **Scenario:** after finalization, both callers pass the guard within one RPC round trip, and both push a piece
  (`state.nextIndex++` twice) with the same signature. Both get the same seed (sha256 of signature + blockhash), so
  two identical NFTs are minted to the buyer for one 0.05 SOL. The supply counter moves by 2, the hot key pays two
  mint fees, and an overpaid or underpaid payment gets two refund records. The window is the RPC latency (~0.1-0.5
  s) against 5 s and 8 s timers. My rough estimate is a few percent of payments made through the page (estimate,
  verify), so tens of duplicates over 2000. No attacker needed. A buyer can raise the odds by paying several times.
- **Evidence:** code path above. Nothing serialises `handlePayment` per signature. The `polling` flag only stops
  overlapping polls, not overlap with the submit loop.
- **Fix:** an in-flight map, or reserve the signature synchronously:
  ```js
  const inflight = new Map();
  function handlePayment(sig) {
    if (!inflight.has(sig)) inflight.set(sig, handlePaymentInner(sig).finally(() => inflight.delete(sig)));
    return inflight.get(sig);
  }
  ```
  Also make `reconcile.mjs` flag two pieces with the same `signature`. Check the existing mainnet state before
  launch (no payments yet, so nothing to clean up).

### H2. Memo dust spam stalls the watcher and floods refunds

- **Where:** `index.mjs:70-101` and `poll()` at 106. Every treasury tx whose memo contains `slowhorizons:` is fetched
  one by one (`getParsedTransaction`), written to `payments.jsonl`, and if `received < price` it becomes a refund
  record with a full `state.json` rewrite + fsync (`store.save()`) and an alert.
- **Exploit:** send N transactions with a 0- or 1-lamport `SystemProgram.transfer` to the treasury plus a
  `slowhorizons:<16 hex>` memo. The cost is about 5000 lamports each: 1000 txs ~ 0.005 SOL. Effects:
  (a) `poll()` handles them one after another. With ~150 ms per fetch, 1000 of them take longer than the 120 s in
  `mintOpen()`, so the page shows "payment watcher behind" and refuses payments (cheap, repeatable closing of the
  mint at launch). (b) `state.refunds` and `state.json` grow, every save rewrites the whole file (O(n^2) disk), and
  `/admin/refunds.csv` fills with junk that someone must sort through by hand. (c) `refund` alerts every 5 min.
- **Evidence:** code. `received` is the treasury's balance delta, so a 0-lamport transfer is accepted as an
  "underpaid" payment. Not run on chain.
- **Fix:** ignore (log only, no refund record, no alert) payments under a floor, e.g. `received < 0.001 SOL`, or
  below the fee it would cost to refund. Cap the work per poll (e.g. 50 signatures) and update `lastPollOk` after
  each batch. Keep pieces paid at full price working during spam by not counting dust as watcher lag. Batch the
  `save()` once per poll, not once per refund.

## Medium

### M1. No Content-Security-Policy; unescaped server data in innerHTML

- **Where:** `web/vercel.json` and `gameboy-labs-site/vercel.json` set nosniff, Referrer-Policy and
  X-Frame-Options only. Live headers (2026-10-18) on `https://www.gameboylabs.xyz/` and `/slow-horizons/` have no
  `content-security-policy`. In `web/mint.js`, `esc()` is used for most fields, but these go raw into innerHTML:
  `p.signature` (`short()` and the explorer href, line 571), `p.mint.assetId` (229, 577), `snap.network` /
  `r.network` (in `?cluster=`), `p.seedHex`, `p.seed` (`data-seed`), `p.seedBlock`, `p.n`, `r.romSha256`,
  `hb.intervals`.
- **Scenario:** these fields are server-generated today, so this is defence in depth. But the mint page shares its
  origin with the main site (www.gameboylabs.xyz) and handles wallet signing. Any way to change API output (tunnel
  hijack, a compromised Mac, a bug that lets a string into `n` or `network`) becomes script on the wallet page. That
  means a drainer, with no CSP to stop the exfiltration or the injected script.
- **Fix:** escape every interpolation (or build with `textContent`), and coerce numbers with `Number()`. Add a
  CSP to `web/vercel.json` (check in the browser console before shipping):
  `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self' https://api.gameboylabs.xyz wss://api.gameboylabs.xyz; img-src 'self' data: blob: https://api.gameboylabs.xyz https://arweave.net; style-src 'self' 'unsafe-inline'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'`.
  (`data:` for Wallet Standard icons; inline `style=` for swatches; `sign.html` has an inline script and needs a
  hash or an external file.) For the main site the same idea with `'wasm-unsafe-eval'` for the meshopt decoder
  (verify). Also add `Permissions-Policy` (camera, mic, geolocation off).

### M2. Public "paste any transaction and sign" page

- **Where:** `web/sign.html`, live at `https://www.gameboylabs.xyz/slow-horizons/sign` (200, verified). It
  deserializes any base64 tx, shows only the fee payer and program names, then `signAndSendTransaction`.
- **Scenario:** (a) Blockaid/Phantom heuristics: a page on the mint domain that asks a wallet to sign an arbitrary
  pasted transaction is the classic drainer pattern, and the domain was already flagged once (LOGBOOK 2026-10-17).
  (b) Social engineering of Hazy: an `updateCollection` that hands the update authority to an attacker, or a
  System transfer, shows only as "Metaplex Core" / "System". The cold wallet is the collection's root of trust.
- **Fix:** take it off the public deploy (add `sign.html` to `web/.vercelignore`) and open it locally only, e.g.
  from the server with `SERVE_SITE=1` on localhost. Decode each instruction (Core: plugin and new authority; System:
  amount and recipient), refuse anything outside an allowlist, and show a hash that `cold-tx.mjs` prints so Hazy
  can compare. Simulate before signing.

### M3. Process user and machine setup

- **Where:** `server/deploy/com.slowhorizons.server.plist` is a LaunchAgent in Hazy's GUI session. SERVER-SETUP.md
  section 7 and LOGBOOK ("automatic login for hazymacmini") rely on auto-login. The same account holds
  `~/.config/cloudflare/gblabs_token` (DNS + rules), the `gh` login (push = deploy, see M6), Vercel CLI, the
  tunnel token and the hot key.
- **Scenario:** any code execution in the server (e.g. a future dependency bug) gives full access to the account.
  The attacker can push a page with a different `seedlab-treasury`, or repoint `www` DNS, then take every buyer's
  SOL, not just the hot key's 0.5 SOL. Physical theft is also easy: macOS disables automatic login when FileVault
  is on (Apple), so auto-login implies the disk is not encrypted at rest (verify `fdesetup status`).
- **Fix:** run the server (and cloudflared) as a dedicated standard user through a LaunchDaemon with `UserName`.
  That user owns only `server/.keys`, `server/data` and `.env` (0600/0700) and has no gh, Vercel or Cloudflare
  credentials. Turn on FileVault and drop auto-login (a LaunchDaemon does not need a login; after a power cut,
  FileVault needs one unlock, or use `fdesetup authrestart` for planned reboots). Keep the Cloudflare and GitHub
  tokens off the mini, or give them their own account.

### M4. RPC quota burn (closing the mint by exhausting Helius)

- **Where:** `/api/ticket` makes one `getLatestBlockhash` per ticket (`index.mjs:429`). `/api/submit` sends any
  structurally correct tx to `sendRawTransaction` with preflight (line 441) without checking signatures, and the
  ticket survives a failed send, so it can be retried 6/min/IP. The watcher, minting and the RPC for these calls all
  share `RPC_URL` (a free Helius key per SERVER-SETUP).
- **Scenario:** a few dozen IPs at 6 tickets + 6 bogus submits per minute each, within the Cloudflare rule of 100
  req / 10 s, keep the free key at its RPS or monthly cap. web3.js then retries 429s with backoff, `poll()` fails for
  120 s, and the mint closes ("payment watcher behind"), and minting stalls.
- **Fix:** cache the blockhash for ~10-20 s and serve every ticket from it. Call `tx.verifySignatures()` before
  relaying, and burn the ticket on any failed send. Use a separate RPC key (or a paid plan) for the watcher and
  minting than for public-triggered calls. Alert on 429s.

### M5. Big unbounded responses and WebSocket churn

- **Where:** `snapshot()` (`index.mjs:351`) puts the whole queue into `/api/state` and into the first message of
  every `/live` connection. The server does not compress. WS upgrades never go through `allow()`; only the 6
  concurrent per IP cap applies.
- **Evidence (local):** 300 queued dev pieces -> `/api/state` = 201,064 bytes, uncompressed even with
  `accept-encoding: gzip`. 200 WS open/close cycles from one IP got 200 snapshots in 178 ms. A slow WS reader is
  never dropped (sends are skipped above 1 MB buffered, but the buffer stays).
- **Scenario:** at launch (hundreds in line) every page load and every reconnect costs 0.2-0.7 MB of the Mac's home
  upload. A handful of IPs at the Cloudflare limit (100 req / 10 s each, ~20 MB/s each at 200 KB) fills a home
  uplink, so the live feed and payments time out.
- **Fix:** send the queue in compact form (n, short wallet, status, drawStart), or only the first ~50 plus counts,
  with an `/api/queue?owner=` / search endpoint. Gzip JSON (or let Cloudflare cache `/api/state` for 1-2 s). Rate
  limit WS connects with `allow(ip,'ws',30)` in a `verifyClient`/`upgrade` handler. Terminate clients whose
  `bufferedAmount` stays above the cap.

### M6. Deploy path for the page that holds the treasury address

- **Where:** the page decides where buyers' SOL goes (`seedlab-treasury` meta in `web/index.html`; the server's
  answer is checked against it, which is good). Vercel deploys `slow-horizons` on every push to `main` touching
  `web/`, and `gameboy-labs` (which proxies `/slow-horizons/`) on every push. GitHub API: both repos private,
  collaborators = hazy2go only, branch protection unavailable on this plan. `gh` is logged in on two Macs used by
  agents.
- **Scenario:** a stolen GitHub token or session (or a careless agent commit) changes one meta tag. Buyers pay the
  new address, and the server sees no payments.
- **Fix:** 2FA with a hardware key on GitHub and Vercel, fine-grained tokens limited to the needed repos, no
  long-lived tokens on the mini. A tiny scheduled check (on the mini, as the server user) that fetches
  `https://www.gameboylabs.xyz/slow-horizons/` and alerts (Discord) when `seedlab-treasury`, `seedlab-api` or
  `seedlab-price-lamports` differ from `.env`. Better still, the server could expose its treasury and the page
  could refuse when they differ. Optionally turn off auto-deploy to production and promote by hand during the mint.

## Low

- **L1. API over plain HTTP, no HSTS.** `http://api.gameboylabs.xyz/api/health` -> 200 (no redirect). The page uses
  https/wss, so the risk is low. Fix: Cloudflare "Always Use HTTPS", HSTS and min TLS 1.2 (refused earlier for lack
  of token permissions, LOGBOOK).
- **L2. In-memory growth.** `tickets` prunes only expired entries and only above 20,000 (`index.mjs:382`); with
  enough IPs it grows past that. `perIp` (502) keeps a 0 entry per IP forever, and `ignoredSigs` (61) is never
  pruned. Fix: hard cap with LRU eviction, delete `perIp` keys at 0, cap `ignoredSigs`.
- **L3. Secret file handling.** On this Mac `server/.env` is `-rw-r--r--` and `/Users/hazy` is `drwxr-x---` group
  `staff`, so any other local account can read it. The mini was set to 600 per LOGBOOK (verify `ls -l` there).
  SERVER-SETUP section 8 puts `ADMIN_TOKEN` on the curl command line (`-H x-admin-token:$T`), visible in `ps`; use
  `curl -H @file` or a small script that reads `.env`. `gameboy-labs-site/.env.local` (Vercel OIDC token, short-lived)
  is 0644, gitignored and not served (404 live).
- **L4. `esc()` does not escape `'`** (`web/mint.js:28`). Every attribute is double-quoted today, so this is safe
  but fragile. Add `'` -> `&#39;`.
- **L5. Dev files public on the main site.** 200 live: `/DESIGN.md`, `/build.sh` (shows local paths), `/render/lab_render.py`,
  `/src/orbit.js`. No secrets. Add them to `gameboy-labs-site/.vercelignore`.
- **L6. Second copy of the mint page at `slow-horizons.vercel.app`** (the address Blockaid flagged). The API's CORS
  only allows www, so it can't take payments, but it keeps the flagged address alive. Redirect it to
  `https://www.gameboylabs.xyz/slow-horizons/` (Vercel domain redirect), then file the Blockaid review for the www
  domain.
- **L7. Sign-only wallet flow.** The page calls `signTransaction`, and the server relays. Phantom recommends
  `signAndSendTransaction`, and sign-then-relay-by-backend is a pattern that wallet scanners weigh (verify current
  Phantom/Blockaid behaviour). If Blockaid flags again, switch to `signAndSendTransaction` (the server still finds
  the payment through the watcher) and drop `/api/submit`.
- **L8. Log line injection (tiny).** A bad JSON body logs `e.message`, which in Node contains a ~10-char raw snippet
  of the body including newlines (tested). Strip control characters in `log()`.
- **L9. orbit.js not reproducible from this repo.** `build.sh` bundles `three` from `~/Projects/gameboy/gb-wallet/web/node_modules`
  (0.186.1, pnpm-locked there) with `npx -y esbuild@0.25.0`. The versions are pinned, but the build depends on another
  repo's install. Add a package.json + lockfile here and record the bundle's sha256 in the LOGBOOK.

## Info

- **I1. `npm audit --omit=dev`** (server/): 37 (3 critical, 7 high, 19 moderate, 8 low), all transitive.
  Reachability: `elliptic`/`secp256k1`/`@ethersproject/*` are Ethereum signing in `@dha-team/arbundles` (we sign
  ed25519/Solana). `ws` 7.x sits under `@ethersproject/providers` (unused; the server's own `ws` is 8.21.0).
  `bigint-buffer` comes through `spl-token` (turbo top-ups, unused). `stream-json`/`uuid` come through `jayson`

  account-compression helpers. **None is on a path that public input reaches.** No action before launch; bump the
  SDKs after the mint. Lockfile v3 with integrity hashes for every package; `turbo-sdk` pinned exactly;
  `@solana/web3.js` 1.99.0 (published 2026-09-08 by GitHub Actions).
- **I2. RPC error text is reflected by `/api/submit`** (`'The network rejected the transaction: ' + first line`).
  Tested with a fake `https://...?api-key=FAKE` URL: web3.js 1.99 uses global fetch, and the error is `fetch failed`
  with no URL, so the Helius key does not leak. HTTP errors show status + body only. OK, but a fixed message would
  be safer.
- **I3.** `server/data-devnet-v1/` (devnet state, wallets, signatures) is committed. It is devnet only, nothing

- **I4.** Discord alerts carry full wallet addresses and stack traces. That is fine for a private channel; treat the

## Verified OK

- **Path traversal:** `/pieces/../state.json`, `%2e%2e`, `..%2f`, `%2e%2e%2f`, `/../server/.env`,
  `/..%2f..%2fserver%2f.env`, `%00` all 404 (local). `serveFile` uses realpath + a prefix check with `path.sep`.
- **Admin:** with the token from localhost = 200; the same request with `cf-connecting-ip` = 404 (local). Live
  `https://api.gameboylabs.xyz/admin/status` = 404. Constant-time compare; the token is required; admin is off when
  `ADMIN_TOKEN` is empty. A browser on the mini can't send the custom header (preflight allows only content-type).
- **CORS:** live API sends `access-control-allow-origin: https://www.gameboylabs.xyz`; `checkConfig` refuses `*`
  on mainnet.
- **WebSocket:** a bad Origin gets close 1008 (local); a 7th connection per IP gets 1013; `maxPayload` 1 KB;
  ping/terminate; client messages ignored.
- **Bind address:** `HOST` defaults to 127.0.0.1, so only the tunnel reaches it, and `cf-connecting-ip` can be
  trusted (Cloudflare overwrites a client-sent value).
- **Body and time limits:** 16 KB body cap (413), `headersTimeout` 15 s, `requestTimeout` 30 s; JSON errors give a
  generic 500 message.
- **Query handling:** `/api/gallery?offset=abc&limit=-5&q=<3000 chars>` and `/api/piece?n=abc` behave (clamped,
  404). Facet values are cut to 40 chars and `q` to 60; the gallery cost is bounded by ≤2048 pieces.
- **No SSRF:** the only outbound requests go to configured URLs (RPC, Arweave, Discord). **No header injection:** no
  request data reaches response headers.
- **Payment checks:** the server's `checkSignedPayment` (exactly 2 instructions, transfer of the price to the
  treasury, our memo, fee payer = sender) and the page's `checkPayment` (treasury and price from page meta, not from
  the server; sender = connected wallet) are correct. The page signs the re-serialized tx it checked. Seeds can't be
  ground (blockhash 32 slots later).
- **Vendored web3:** `web/vendor/web3.iife.min.js` sha256 `09cdbea9…88cc3` = `@solana/web3.js@1.98.4`
  `lib/index.iife.min.js` from npm (published by solana-devs, 2025-07-31; not the compromised 1.95.6/1.95.7).
  There are no third-party scripts, fonts or iframes on either site.
- **XSS from user data:** wallets reach the page only from chain data or the devnet-only `/api/dev/pay`. A test
  wallet `<img src=x onerror=…>` is stored, but every place it renders (`short`, queue search echo) is escaped.
  Wallet Standard name and icon are escaped. No `postMessage` and no `eval`.
- **`?as=` hook:** only on localhost/127.0.0.1. It sets the displayed wallet only, cannot sign (no provider).
- **Scripts:** `demo.mjs` binds 127.0.0.1:8795 (the tunnel ingress is 8791 only), sits outside the Vercel root
  (`web/`), and refuses ticket and submit. `cold-tx.mjs` only prints unsigned txs. `mainnet-setup.mjs` defaults to
  a dry run, refuses a second collection, and refuses a cold authority equal to the hot key or the treasury.
  `/api/dev/pay` needs `DEV=1` and devnet, and `checkConfig` refuses `DEV=1` on mainnet.
- **Secrets in git:** no keys, tokens, webhook URLs, Helius keys, PEM blocks or 64-byte key arrays in either repo's
  full history (pattern search; the hits were tx signatures and a Bayer matrix). `.gitignore` covers `.env`,
  `.keys/`, `data/`, `.vercel`. Live: `/.env.local` and `/.git/config` = 404, mint `lab/` = 404.
- **Permissions on this Mac:** `server/.keys` 700, `authority.json` 600, `~/.cloudflared` 700 / token 600.
- **Vercel headers:** nosniff, Referrer-Policy strict-origin-when-cross-origin, X-Frame-Options SAMEORIGIN and HSTS
  are present on both pages (CSP missing, M1).

## Suggested order

C1 now (one line, before launch). Then H1 and H2 (both in `handlePayment`/`poll`). Then M4 and M5 (before the
launch crowd), M2 (take `sign.html` off the public site), M1 (CSP + escaping), M6 (live meta check), M3
(dedicated user + FileVault) when there is time on the mini. The Lows can wait.
