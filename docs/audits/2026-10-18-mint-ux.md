# Mint page and mint process audit (2026-10-18)

Scope: `web/index.html`, `web/mint.js`, `web/mint.css`, `server/src/index.mjs` (+ gallery, solana, storage, lanes), from the buyer's side. Read-only: no project file changed except this report and its images.

How it was tested

- A scratch copy of the demo with state controls (offline/online, closed/open, sold out, abort, pause, seeding-only line, 2000 in line, failing submit, collector pieces + refunds) and a fake Wallet Standard wallet that signs with a real keypair, so the page's buy flow ran end to end (ticket, checkPayment, sign, submit, queued, seeded). - Code moved during the audit (commits b808ba8 .. 8a8ad5b, 00:25-00:33). Line numbers below are for HEAD 8a8ad5b. C2, C3 and H1 were re-run on that version and still reproduce.

Fixed by other commits while this audit ran (not counted below)

## Critical

### C1. Page breaks when the oldest entry in line is still waiting for its seed
- **Where:** `web/mint.js:280` calls `renderLabel(live.piece || snap?.queue?.[0])`; `renderLabel` (`:122-125`) reads `p.traits.palette`, but a `seeding` piece has `traits: null` (`server/src/index.mjs:106`, `publicPiece :350`).
- **What:** whenever nothing is drawing and the oldest piece in line is still seeding (the first purchase after an idle studio, which is exactly launch, and every visitor or reconnect during that ~15-30 s window), `renderAll` throws on its third step. Price, queue, wall and buy button never render: "Studio open, the Game Boy is waiting for a commission" next to a disabled **"Studio offline"** button, no price, "Nobody in line" although someone is.
- **Repro:** demo copy with one seeding piece and no drawing; open the page. Console: `Cannot read properties of null (reading 'palette')`.
- **Evidence:** `06-seeding-first-crash.jpg`.
- **Why the demo never showed it:** `demo.mjs:34-38` gives seeding pieces a seed and traits, unlike the real server.
- **Fix:** `renderAll`: `live.piece || snap.queue.find(p => p.traits) || null`; `renderLabel` handles `!p.traits` ("No. N · paid, seed coming"). Wrap each render step in try/catch so one failure cannot blank the rest. Make the demo's seeding pieces `seed: null, traits: null`.

### C2. After paying, the buy button re-arms in 4 s and nothing durable says "you paid"
- **Where:** `web/mint.js:446` (`finally { setTimeout(() => { busy = false; renderBuy(); }, 4000) }`), `:313-318` (button text set once, overwritten by the next `renderAll`), `:440` (note), `:331-336` (`bump` drops `seeding` pieces, see H5).
- **What:** timeline with the fake wallet (finalization simulated at 15 s, seed at 28 s): 0.5 s "Paid. Waiting for the network…", **4.1 s "Commission a piece for 0.05 SOL" (enabled)**, 15 s "Paid. You are No. 558." for 1.5-3.5 s, then back to "Commission a piece…". "Your place in line" appears only at 28 s (after the seed). On mainnet the gap is 15-45 s. A buyer who looks up from the wallet sees a fresh buy button and an unchanged line and pays again. Reloading in that window shows nothing (`waitingFor` lives in memory only).
- **Evidence:** `08-buy-sign-3s.jpg`, `08-buy-sign-10s.jpg` (button live again; only the small grey note hints at a payment).
- **Fix:** a persistent "Payment sent" card (signature, explorer link, "waiting for the network, then your number") that stays until a piece or refund for that signature appears; save `{signature, wallet, at}` in localStorage and restore it on load; relabel the button "Commission another piece" (with a confirm) while this wallet has a pending payment; add `GET /api/payment?sig=` (pending / piece N / refund) and poll it instead of relying only on WebSocket events.

## High

### H1. Network rejections are shown as "You cancelled in the wallet. Nothing was paid."
- **Where:** `web/mint.js:443` regex `/reject|cancel|declin/i`; the server's text is "The network rejected the transaction: …" (`index.mjs:457`).
- **What:** expired blockhash (buyer took more than ~60-90 s in the wallet, common on phones), insufficient SOL, any preflight failure all contain "rejected", so the buyer is told they cancelled. A Wallet Standard rejection without those words shows a raw error ("WalletSignTransactionError").
- **Repro:** demo copy with `/api/submit` answering "The network rejected the transaction: Transaction simulation failed: Blockhash not found" (also tried "…no record of a prior credit"). Toast: "You cancelled in the wallet. Nothing was paid."
- **Fix:** classify by stage, not text. Errors from `provider.signTransaction` with `code === 4001` / a rejection name are cancels; errors from `/api/submit` are network errors with their own copy: blockhash expired -> "The approval took too long and the payment expired. Nothing was paid. Try again."; insufficient funds -> "Not enough SOL: you need 0.05 SOL plus a small network fee." Better still: `/api/ticket` checks the wallet balance (the server has the RPC) and refuses before the wallet opens.

### H2. Open/closed, sold count and sold out go stale after page load
- **Where:** `mintOpen`, `mintClosedReason`, `sold`, `secondsPerPiece` only arrive in the snapshot (`index.mjs:366-376`), sent on connect and on /admin/open|close (`:489-490`). Lane changes send `{type:'lane'}` (`:165-166`) and the page only copies `snap.lane` (`mint.js:320`). `renderBuy` (`:268-279`) and `renderPrice` (`:259-267`) read the stale fields.
- **What:**
  - Game Boy goes offline while a tab is open: status "Studio closed: the Game Boy is not connected", buy button still **enabled** (`10-offline-live.jpg`); a click gets a 503 toast.
  - Tab opened while offline, Game Boy comes back: status "Drawing No. 413", button stays **"Closed while the Game Boy is offline"** until reload (`13-online-but-button-closed.jpg`). Every tab open during a lane blip can no longer buy.
  - "675 of 2000 taken" stayed frozen for 36 s while the server went to 680 (measured). The meter never moves; sold out never shows live; "payment watcher behind" and the new "minting wallet empty" (`index.mjs:68`, no page text for it, falls back to "Closed right now") never clear.
- **Fix:** broadcast `{type:'mint', mintOpen, mintClosedReason, sold, secondsPerPiece}` whenever any of them changes (lane ready/down, payment recorded, pause/resume, poll age crossing 120 s, hot balance), or include them in every `lane`/`queued`/`status` message; `bump()` also increments `snap.sold` for new pieces.

### H3. An aborted drawing stays "Drawing No. N" on every open page
- **Where:** `abort()` (`index.mjs:220-230`) and the mismatch path (`:241-247`) only broadcast `status: queued` / `lane`; the page clears `live` only on `drawn` (`mint.js:308`) or a new snapshot (`:291-292`).
- **What:** Game Boy dies or stalls (150 s watchdog), restarts mid-drawing, or the tiles mismatch: the studio keeps "LIVE · seed" and "Drawing No. 413 on the Game Boy, ridge done", and the foot counts down to "about 0:00 to go" and stays there (measured 31 s after the abort, unchanged; `09-abort-stuck-drawing.jpg`). After a mismatch on phase 8 the status reads "…done done". Nobody learns why; the collector is not told the piece will be redrawn.
- **Fix:** broadcast `{type:'aborted', n, reason, willRetry}`; the page resets `live`, writes the reason in the studio foot ("The Game Boy stopped answering. No. 413 goes back to the front of the line and is drawn again from the start; nothing is lost.") and toasts the owner's wallet.

### H4. While drawing is paused, the page keeps selling and says the studio is waiting
- **Where:** `mintOpen()` (`index.mjs:63-71`) ignores `lanePaused` (set after 3 faults in a row or a mismatch, `:228`, `:243`; now saved across restarts, cleared only by /admin/resume). `renderStatus` (`mint.js:161-170`) ignores `snap.lane.paused`.
- **What:** with drawing paused (waiting for Hazy), a fresh tab shows "Studio open, the Game Boy is waiting for a commission", buy enabled, queue ETAs "in ~3 min". Buyers pay into a line that does not move, possibly all night.
- **Fix:** `mintOpen` returns `{open:false, reason:'paused'}` when `lanePaused`; page text "Paused: the Game Boy needs a check. Paid pieces keep their place and are drawn when it resumes." ETAs show "paused".

### H5. New payments are missing from the line until their seed, and refunds never show live
- **Where:** `bump()` (`mint.js:331-336`) keeps only `queued|drawing`; the server announces a new piece as `{type:'queued', piece:{status:'seeding'}}` (`index.mjs:112`). The snapshot includes seeding pieces (`:367`), events do not.
- **What:** open tabs never show "Getting its seed" rows (measured: server 260 in line with 2 seeding, page 258 and no seeding rows), so the "Paid. Your seed arrives…" line in the your-place card (`mint.js:228`) is unreachable for the buyer who just paid. A payment that becomes a refund (sold-out race at the end, closed) sends no event: `waitingFor` never resolves, the buyer sees "Paid. Waiting for the network…", then a normal buy button, and nothing else.
- **Fix:** treat `seeding` as in line in `bump()`; broadcast `{type:'refund', wallet, signature, reason}` and show it in the payment card (C2) and in "Your pieces".

### H6. Copy promises things that do not exist at launch
- **Where / what:**
  - `index.html:112` evidence 5 "The camera. The real screen, filmed, with the seed shown on it." and the Camera tab (`:39`) "The camera goes live with the first session on the real Game Boy". There is no camera or `STREAM_URL`, and the first session on the real Game Boy is the launch.
  - `index.html:70` "come back any time to watch the recording of yours." There is no recording; there is a digital replay.
  - `index.html:108` "a few parts per million off its nominal" above a live reading of −57 ppm; and the number is the offset against the Pico's own crystal (MINT.md), not the crystal's absolute error.
  - "On the link cable" panel: idle mode prints synthesized `00` bytes and data mode re-times tile bytes without framing (`mint.js:512-558`), while its labels imply real traffic.
  - MINT.md: "Honesty is the selling point."
- **Fix:** evidence 5 "Camera: coming later. Until then each piece records its draw time and the exact tiles the Game Boy sent."; Camera tab "No camera yet."; fine print "come back any time to replay how yours was drawn."; heartbeat "tens of parts per million off nominal, timed against the bridge's own crystal"; bus label "tile data, replayed at cable speed", idle as "idle".

### H7. Shared IPs and fast scrolling can lock buyers out
- **Where:** WebSocket cap 6 per IP (`index.mjs:522`, close 1013), 600 req/min per IP (`:433`), ticket/submit 6/min (`:438`, `:448`), Cloudflare rule 100 requests / 10 s per IP (LOGBOOK 2026-10-17). Every wall and gallery image is an API request (`mint.js:243`, `:644`) served `no-cache` with a `?s=` key (`index.mjs:417`).
- **What:** mobile carriers (CGNAT) and venue/office Wi-Fi put many buyers behind one IPv4 (verify for this audience). The 7th tab on that IP is closed and the page silently retries, showing "The studio is offline right now." The gallery loads 24 images per batch with 600 px look-ahead; a fast scroll, or two people on one Wi-Fi, passes 100 requests in 10 s and Cloudflare blocks the IP for 10 s: images break, the WebSocket drops, a ticket fails.
- **Fix:** piece images with `cache-control: public, max-age=31536000, immutable` (they never change) so Cloudflare serves them, or from Arweave/Vercel; exempt `/pieces/` from the rule; raise the WS cap and show a clear message on close 1013.

### H8. A submit that times out on the buyer's side leads to a second payment
- **Where:** `index.mjs:456-458` (ticket deleted after relaying), `:450` ("Unknown or expired ticket. Start again; nothing was charged."); `mint.js:437`, `:443`.
- **What:** on a flaky phone connection the relay succeeds but the response is lost: toast "Failed to fetch". Retrying the same ticket is told "nothing was charged" although the first payment is on its way; clicking buy again pays twice.
- **Fix:** remember relayed tickets as `{signature}` for 10 minutes and answer a repeat submit with the same signature (202); after any submit error the page checks the pending endpoint (C2) before offering a new purchase; never say "nothing was charged" on the submit path.

## Medium

### M1. Offline and connection drops show a wrong, empty studio
- **Where:** `ws.onclose` sets `snap = null` (`mint.js:328`); `renderQueue` shows `#queueEmpty` without a snapshot (`:190`); `renderWall` empties the wall (`:251-258`); `renderLabel(null)` text (`:124`).
- **What:** a 1-2 s WebSocket blip collapses the page from 5255 px to 2351 px (the reader loses their place) and shows "Nobody in line. The next commission starts right away." and "No pieces yet." With no server, or with commissions closed, the label says "Nothing on the easel. The next commission starts as soon as it is paid." (`07-no-server.jpg`, `14-closed-prelaunch.jpg`, `18-ws-drop.jpg`). Reconnect itself works (1 s).
- **Fix:** keep the last snapshot on close and mark it stale ("Reconnecting… as of 12:04"); show "Nobody in line" only when a snapshot says so; per-state label text (closed: "Commissions open on <date>"; offline: "The Game Boy is not connected right now").

### M2. Pieces still in line can be seen before the Game Boy draws them
- **Where:** `openPiece` (`mint.js:569-573`) only refuses pieces without traits; queued pieces have traits once seeded. `/api/piece` serves any piece (`index.mjs:463-466`).
- **What:** `#piece-422` for a piece still in line opens the sheet with the final picture, banner download, "Drawn: not yet", "On chain: queued" (`17-queued-piece-revealed.jpg`). It spoils the live reveal the product is built around.
- **Fix:** open the sheet only when `drawEnd` is set; otherwise "No. 422 is in line (37 ahead). Its picture appears when the Game Boy draws it." Optionally leave traits out of `publicPiece` until drawn.

### M3. Gallery filters and search lose changes
- **Where:** `loadGallery` returns early while a load runs (`mint.js:625-626`); filter `change` (`:655`) and search (`:658`) call it.
- **What:** on a slow connection, choosing palette "Original" then time "night" left 21 results with "night" selected but 18 of them not at night (measured, `20-gallery-filter-race.jpg`). The error toast says "Retrying in a moment" (`:638`) but nothing retries. Newly drawn pieces never appear until reload.
- **Fix:** AbortController per request and always load the latest filters; real retry with backoff; prepend pieces on `drawn` events when sorted newest first.

### M4. The piece sheet fights the Back button
- **Where:** `history.replaceState` on open (`mint.js:600`) and close (`:621`).
- **What:** opening a piece adds no history entry, so Back (or the phone's back gesture) leaves the page or the view instead of closing the sheet (measured: opened from the gallery, Back left the site). Closing drops the query string.
- **Fix:** `pushState` on open, close on `popstate`, keep `location.search`.

### M5. Phone layout: buy button below the fold, no ETAs, inputs zoom
- **Where:** `mint.css:183-206`, `:195`, `:212`, `:250`, `:137`.
- **What (iPhone 393x852):** the buy button starts at y=888, below the first screen (`01-demo-iphone.jpg`); the "Starts" column is hidden, so the line on phones has no times (`04-iphone-queue.jpg`); the search input and gallery selects are 14 px, so iOS Safari zooms on focus (the jumpy zoom Hazy reported); the "Finished" wall is one column, 10,600 px (page 14,600 px); 53 tap targets under 40 px (Replay/On chain links 22 px tall); the line search placeholder is cut ("Wallet address or N").
- **Fix:** on phones put price + button above the cable panel or a sticky bottom bar "Commission · 0.05 SOL"; keep Starts, move Collector to a second line; 16 px inputs and selects; wall in 2 columns with 12 pieces and "See all in the gallery"; 44 px tap height.

### M6. Mobile wallet onboarding and wallet state
- **Where:** `connectWallet` (`mint.js:406-420`), wallet button (`:421`).
- **What:** in a normal phone browser (most visitors from X/Discord) the only help is a 7 s toast; no "Open in Phantom / Solflare / Jupiter" links, no Mobile Wallet Adapter on Android Chrome. After a reload the wallet is forgotten and "Your place" disappears until the buyer connects again. No disconnect or account switch: change account in the wallet and the page keeps the old address. Connected with no pieces, the wallet button scrolls to a hidden section and seems dead.
- **Fix:** a mobile sheet with deep links (Phantom `https://phantom.app/ul/browse/<url>?ref=<origin>`, Solflare `https://solflare.com/ul/v1/browse/<url>`; check Jupiter's); silent reconnect on load (`standard:connect` with `{silent: true}`, Phantom `connect({onlyIfTrusted: true})`); listen to `standard:events` / `accountChanged`; a wallet menu with "Your pieces" and "Disconnect".

### M7. Wait times and counts disagree
- **Where:** `renderPrice` (`mint.js:262-264`), `renderQueue` (`:191-199`), `renderMyPlace` (`:225-229`), `renderStudioFoot` (`:177-179`).
- **What:** the price row uses the whole line in plain minutes ("1998 ahead, about 2831 min") while the table uses hours ("in ~47 h") and the your-place card counts only pieces ahead of yours ("40 ahead of you · starts in about 46 min" right under "149 ahead, about 174 min", `03-iphone-commission.jpg`). ETAs ignore offline and paused. The studio countdown sticks at "about 0:00 to go" on a long draw.
- **Fix:** one formatter (minutes under 90, then hours, then "about N days"); price row "N in line · a new piece starts every ~85 s"; "waiting for the Game Boy" when offline/paused; "finishing up" after 0.

### M8. Heavy snapshot and images
- **Where:** `snapshot()` sends every queued piece in full (`index.mjs:373`); ws `perMessageDeflate` is off by default; thumbnails use the 6x PNG (`mint.js:243`, `:644`).
- **What:** with 2000 in line the snapshot is 1.47 MB (354 KB gzipped) on every connect and reconnect, through the tunnel. Wall and gallery tiles load 960x864 PNGs (~21 KB) for 250 px slots; the 1x PNG is ~2.5 KB and scales crisply with `image-rendering: pixelated`. Scrolling a 2000-piece gallery: ~42 MB vs ~5 MB.
- **Fix:** queue rows as `{n, short, status}` (detail on demand) or `/api/queue?offset`; enable `perMessageDeflate`; `.1x.png` for thumbnails, the big PNG only in the sheet; immutable cache headers.

### M9. Accessibility gaps
- **Where / what:**
  - Focus ring is `var(--ink)` (`mint.css:39`): 1.05:1 on the dark studio, invisible on the channel tabs (`23-focus-ring-studio.jpg`).
  - Wall and "Your pieces" images open the sheet by mouse only (`<img data-open>`, `mint.js:243`, `:478`): 0 of 24 reachable by keyboard (the gallery uses buttons, good).
  - `--muted` #74726b on the wall is 4.17:1 (3.84:1 on #ede5d2): fine print, table headers, labels and placeholders are under 4.5:1.
  - No `h1` on the studio view (the only h1 is in the hidden gallery view); canvases have `aria-label` but no `role="img"`; 24 identical "Replay the draw" / "On chain" names; status line, your-place card and progress are not live regions (only the toast is). Channel tabs lack `aria-controls` and arrow keys.
- **Fix:** light focus ring inside `.studio` (`outline-color: currentColor`); wrap images in buttons; `--muted: #66645d`; a visually hidden h1; `role="img"`; `aria-label="Replay the draw of No. 273"`; throttled `aria-live="polite"` on `#statusText` and `#mpLine`.

### M10. Before launch and after sell-out the page gives no direction
- **Where:** `renderStatus` (`mint.js:168`), `renderBuy` (`:274`), `renderLabel` (`:124`).
- **What:** the live site right now says "Commissions are closed right now", no date, no link to follow, and "Nothing on the easel. The next commission starts as soon as it is paid." Sold out shows the generic "commissions are closed right now" in the status line and "no wait".
- **Fix:** a `launchAt`/message field from the server: "Opens Oct 25, 18:00 UTC. Follow @… for the start."; sold out: "Sold out: all 2000 pieces taken. See the collection."

### M11. Failures after drawing are opaque to the collector
- **Where:** "Your pieces" statuses (`mint.js:477`), refunds (`:482`).
- **What:** an Arweave upload failing or a mint not landing shows "Drawn, minting" / "Minting" with no time or reason, indefinitely. "Needs a look; it will be redrawn or refunded" has no time frame. A refund for a payment made while closed before launch reads "arrived after minting ended". Minted rows have no on-chain link. Small overpayments read "0.0000 SOL".
- **Fix:** add `since` and a short public reason (`storing`, `minting, retrying`) to `publicPiece`; after 10 min "Taking longer than usual. It is safe and will reach your wallet."; reason `closed` -> "arrived while commissions were closed"; a refund promise ("within 48 h"); "View on chain" for minted; SOL with up to 9 decimals.

### M12. The demo hides real states
- **Where:** `server/scripts/demo.mjs:34-38`, `:120`.
- **What:** seeding pieces carry seeds and traits (so C1 never reproduces), `/api/pieces` always returns empty (no "Your pieces", refunds or pending states), the mint is always open, no aborts or pauses.
- **Fix:** mirror `publicPiece` exactly; add switches like the scratch copy used here (offline, closed, sold out, abort, pause, seeding-only, collector pieces and refunds, fake ticket/submit).

## What is good

- Performance under load: 2000 in line, one new piece per second, phases every 1.5-2.5 s for 3 minutes: no long tasks, JS heap flat at ~4 MB, DOM bounded (line paged at 10, wall capped at 24), search typing responsive. About 220 KB/min of WebSocket traffic per viewer while drawing.
- Payment safety: the page signs only an exact transfer of the published price to the published treasury with our memo (`checkPayment`), the server re-checks the signed bytes before relaying, and server data is now sanitized on arrival. Payments count even without a known ticket, so closing the tab after signing cannot lose a payment.
- Server robustness: cursor-based treasury watcher, one in-flight check per signature, restart turns `drawing` back into `queued`, pause survives restarts, mint signature recorded before sending, append-only payment and event logs, refunds recorded rather than lost.
- No horizontal overflow at 360, 393, 1280, 1440 or 1920 px; the desktop layout is calm and readable; the studio plus wall-label idea works.
- WebSocket reconnect is fast (1 s) with backoff; `#piece-N` deep links and "Copy link" work; reduced motion is respected for the canvas wipe and palette fade.
- The evidence section is structured the right way (what each piece of evidence shows and what it does not), and the page says plainly that a server, not a contract, runs the line.
